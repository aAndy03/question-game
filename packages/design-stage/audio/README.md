# Cue pack

The eight `.wav` files here are **placeholders** — plain synthesised tones,
one distinct pitch and envelope per cue so an operator can tell them apart
while auditioning the cue map. They are generated by
`npm run audio:placeholders` (`scripts/audio-placeholders.ts`) and committed.

## The file names are the contract

Stage plays a cue by **key**, never by file: `manifest.ts` maps each key of
`CUE_KEYS` (`packages/contract`) to `<key>.wav`, and nothing above that
adapter names a file.

| Cue key | File | Plays when |
| --- | --- | --- |
| `lock` | `lock.wav` | the working choice is locked |
| `correct` | `correct.wav` | the outcome is revealed as correct |
| `wrong` | `wrong.wav` | the outcome is revealed as incorrect or partial |
| `overlay_start` | `overlay_start.wav` | an Overlay animation starts |
| `play_start` | `play_start.wav` | the Play goes from loaded to playing |
| `timer_start` | `timer_start.wav` | the question timer starts running |
| `timer_pause` | `timer_pause.wav` | the question timer is paused |
| `timer_expired` | `timer_expired.wav` | the countdown reaches zero before a reveal |

## Replacing a sound

Overwrite the file with the same name. Keep it short (the placeholders are
under half a second) and in a format the webview decodes — WAV or MP3 are
safe. No code changes: Stage's Vite config serves whatever is in this folder
under `/stage/audio/` in dev and copies it into `dist/stage/audio/` on build.

Running `npm run audio:placeholders` again **overwrites** every file with the
placeholder tone; do not run it after installing a real pack.

A file that fails to load is reported by Stage to the host (`stage_report`)
and surfaces in Studio as the `health.audio_missing_cue` notice.
