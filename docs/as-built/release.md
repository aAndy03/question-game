# Releasing as built

Identities, the installer, single instance, uninstall, the licence audit, CI, updates and What’s new. The rules here are binding; `CLAUDE.md` points here instead of carrying them.

## Two identities, and a release that reports on itself (P12.0–P12.1)

- **A third identity, `org.questiongame.e2e`, is the end-to-end suite's** (P12.14): a built app, never a dev server, in folders of its own.
- **Dev and the installed app never share a folder.** `tauri.conf.json` is production (`org.questiongame.desktop`); `tauri.dev.conf.json` overrides only the identifier (`org.questiongame.app`, where the dev library has lived since P5). The library, the log, the lock, the WebView2 profile, the single-instance key, and what the uninstaller's *Delete the application data* box removes are all keyed on it. `crates/app/tests/identity.rs` holds the two files and `identity.rs`'s constants together.
- **The identity check comes before anything resolves a path.** `identity::check(tauri::is_dev(), identifier)` refuses a dev binary with the release identity (a plain `cargo build` run by hand) and a release binary with the dev one, through the boot message box. Do not remove it to make a manual run work — run `npm run dev:app`.
- **A release build's perf log is host-side.** `os` (every process in the tree, WebView2 included), `host` and `spike`, with `"build": "release"`. The webviews post nothing: `installDiagnostics` / `installStageDiagnostics` gate the sweep, `perf_report`, the watchdog's `Profiler` and `crumb()` on `import.meta.env.DEV`, which Vite folds so the code is not in the bundle. Studio's error forwarding (`error`, `unhandledrejection`, `console.error`/`warn`) is the one webview line a release keeps. Branch on `import.meta.env.DEV` directly — a parameter defaulted to it is not tree-shaken.
- **Bounded files.** Old perf runs: ten and 100 MB (`perf::prune`, before the new run exists). `questiongame.log` rotates at boot past 10 MB, keeping three (`logfile::rotate`).
- **A release has no console**, so `boot::install_panic_hook` writes panics to the log and `boot::fail` shows a boot failure in a message box (`rfd`) before exiting. `setup` is identity → logging → panic hook → `start()`; an error from `start()` is shown, not swallowed.
- `paths_get` answers `logFile`, `perfDir`, and `cuePack: null` when the pack folder is not on disk (a release embeds it).

## Single instance, the close guard, and uninstall (P12.2)

- **NSIS, `currentUser`, unsigned.** One version in three files (`Cargo.toml` `[workspace.package]`, `tauri.conf.json`, root `package.json`), held together by `crates/app/tests/bundle.rs`. Bump all three together.
- **`tauri-plugin-single-instance` is the first plugin on the builder**, by its own rule: a second process must find the first before it builds anything. It is keyed on the identifier, so dev and the installed app each have their own. `state::take_single_instance_lock` stays as the library's own guard.
- **The close guard is `quit::QuitState`.** The first `CloseRequested` on `main` is prevented and emits `close-requested`; Studio answers `app_quit` or `app_close_cancelled`; a second press while a request is open exits regardless. Studio routes the question through the nav guard with `QUIT_ROUTE` and `askLeave()` (`05_STUDIO_DESIGN.md` §18.1). **Never add a close path that cannot be escaped.**
- **`uninstall_data` clears the WebView2 profile outside the lock** (`clear_all_browsing_data`), then removes the data folder.
- **`app_uninstall` exists only where `uninstall.exe` sits beside the exe** (`commands::app::uninstaller_beside`); `paths_get.uninstaller` tells Studio whether to draw the row. It refuses, in order: no uninstaller, a loaded Play, a missing pin.

## Notices, the licence audit, the release check, and CI (P12.3)

- **The licence audit is the notices generator.** `scripts/lib/notices.ts` holds `ALLOWED` (SPDX ids) and `EXCEPTIONS` (exactly `gsap` and `@gsap/react`); `scripts/notices.ts` walks `cargo metadata` (normal edges from `questiongame-app`) and `npm query .prod`, and **fails `npm run build`** on anything else. A new dependency under another licence is a decision, not a warning — do not widen the list to make a build pass.
- **The notices are files, not a command.** `apps/studio/public/notices/` (gitignored) → `dist/studio/notices/`, read by `AboutPanel` over `BASE_URL`. `LICENSE` is copied verbatim; the GPL forbids changing it, so the GSAP §7 permission lives in `README.md`, About and the notices header instead.
- **`release:check` runs in `beforeBuildCommand`**, so every `tauri build` is checked: no `http(s)://` script, stylesheet, image, `url()`, `fetch` or `import()`; no `localhost:5180/5181`; no `perf_report` call site; no `__QG_FAKE_HOST__` (`fake.ts`'s marker). Rules are in `scripts/lib/release-check.ts`, tested both ways.
- **CI releases.** `.github/workflows/release.yml`: on a `v*` tag it runs every suite on Windows, refuses a tag that does not match `package.json`, then `tauri-action` builds `nsis` on Windows and `--target universal-apple-darwin` on macOS and attaches both to the release named after the tag. *Run workflow* builds without publishing. `tauri.macos.conf.json` is merged by the Tauri CLI on macOS only. The macOS build has not been run on a Mac yet; the Rust tree cannot be cross-checked from Windows (`objc2-exception-helper` needs Apple's C toolchain), so CI is its first compile.
- **The installers are unsigned** on both platforms (`signingIdentity: "-"` is an ad-hoc signature). README says what SmartScreen and Gatekeeper show and how to get past them; keep that text in step with the release body in the workflow.

## An update copies the library first (P12.6)

An operator updates by installing the new build over the old one; the library stays in `<app data>` and the new build opens it.

- **No copy, no change.** `CatalogService::open_file` (through `db::open_guarded`) copies an existing library with `VACUUM INTO` to `<app data>/backups/questiongame-<old version>-<yyyymmdd-hhmmss>.sqlite3` **before** `migrate` and before the projection rebuild — the first write. It copies when a migration is pending or a different build opened the file last. A copy that cannot be written is `CatalogError::BackupFailed`, shown by `boot::fail`, and the file is untouched.
- **Which build opened it last is a row, not a schema change**: `app.last_opened_version` in `globals` (`META_LAST_OPENED`), so a 1.0.1 binary still opens a library 1.0.2 has stamped. An unstamped library was last opened by 1.0.1 (`UNSTAMPED_VERSION`). The next schema migration is still forward-only; the copy is the way back.
- **The host has no version and no clock**: `state::open_options` passes `CARGO_PKG_VERSION`, the folder and a UTC stamp. `CatalogService::open` (no copy) stays for memory and tests; the app boots with `Host::open_installed`, which keeps the `OpenReport` on `Host` for *What's new*.
- Five copies are kept, pruned **right after the copy is written** (so a boot that fails later cannot pile them up) and **never the copy just taken** (the order is the clock's, and a clock that is behind would make it the oldest); `prune` touches only names it wrote, and a failed `VACUUM INTO` removes its half-written file. `crates/host/tests/upgrade.rs` is the suite; Settings ▸ Data lists the folder.
- **The copy before workspaces is pinned** (Beta 2.0, migration 4): when step 4 is still pending, the copy is `questiongame-pre-workspaces-<stamp>.sqlite3` instead of the usual one, and `prune` never deletes a name with that prefix — later upgrades cannot push out the one copy of the library as 1.x left it. A Beta copy of the stable library takes the same pinned copy, because the copy is a 1.x library. *Delete permanently* (a workspace) takes a `questiongame-pre-delete-<stamp>` copy in the normal rotation.
- **A 1.0.2 → 1.0.1 → 1.0.2 round trip takes no second copy**: 1.0.1 does not restamp, so the second 1.0.2 boot finds its own stamp. The schema is the same on both sides, so nothing is at risk; a future migration still copies first, because a pending migration is the other trigger.

## A newer release is mentioned, never installed (P12.9)

- **`crates/app/src/update.rs` is the app's only network call.** `update_check` → `check(fetch, CARGO_PKG_VERSION, channel.line())`; the fetch is a parameter (it is handed the path, so a test can assert which one), so parsing (drafts, prereleases and non-semver tags ignored) and semver comparison (1.0.10 > 1.0.9) are tested without a network. `crates/app/tests/update.rs` has one `#[ignore]`d live test — run it with `--ignored` before a release.
- **TLS is rustls + ring, trusting the OS roots** (`rustls-native-certs`). Not `native-tls`, `platform-verifier` or ureq's default roots: each pulls `webpki-root(-cert)s`, CDLA-Permissive-2.0, which the licence audit refuses. `native-tls-no-default` *compiles* and then panics on the first https call — the live test is what found it.
- **`update_check` is an `async fn` that runs the request on the blocking pool** (`spawn_blocking`, P12.12): five seconds of waiting must not occupy an async worker the other commands need. It is still never on the event-loop thread. A failure is `warn!`ed — Studio says nothing about it, so the log is where *offline* and *no trusted roots* differ.
- **Studio passes a version, never a URL.** `update_open_release { version }` parses it and builds the page itself; `commands::flags::os_open` is the one OS opener (`paths_reveal` uses it too).
- **What's new (P12.10) is operator copy, not a changelog.** `copy/whatsNew.ts` holds each release's notes in plain words in every language Studio can show (en, ro); `whatsNew.test.ts` holds the languages together and refuses developer words. **Every release adds its entry at the top before the tag.** The host only says where the notes start (`whats_new_get` via `crates/app/src/whats_new.rs`: `app.last_seen_version`, else 1.0.1 for a library that existed **and carried no `app.last_opened_version`** (P12.12: a library 1.0.2 created was stamped by it, so a first boot closed before Studio asked is not mistaken for a 1.0.1 library), else stamp a new library silently); `host/whatsNew.ts` shows the window once, never over a loaded game; *Got it* calls `whats_new_seen`.
- **When to ask is chrome**: `host/updates.ts` asks once per process (a module flag, so StrictMode and remounts do not repeat it), only when `updates.check_on_start` is on and **no game is loaded** — and only once the host has *said* so: `usePlayStateKnown()` is false until the first `get_state` or `play-state`, because before that an empty store is "not known", and a show resumed at boot is a Play Studio has not heard of yet (What's new waits on the same flag), and pushes an `info` notice `update.available` only when the answer is newer. Offline, up to date or refused: nothing. Settings ▸ About has the switch and *Check for updates*, which answers inline.

## Channels: questiongame and questiongame Beta (P13.0)

Two products ship from one repository. **questiongame** is the stable app people run shows on; **questiongame Beta** carries the next major version, installs beside it, and keeps its own library. Their data meet only when Beta copies the stable library, read-only, on its first launch (P13.1).

- **`identity::channel` is the one place the channel is decided**: `Stable` (`org.questiongame.desktop`), `Beta` (`org.questiongame.beta`), `Dev` (`org.questiongame.app`) and `E2e(Line)` — the e2e build playing either product, picked by `QUESTIONGAME_E2E_CHANNEL` (`stable` | `beta`). Only the e2e identity reads that variable, and it **refuses** a value it does not know: a typo that quietly ran the stable specs would pass for the wrong reason. The channel is decided once in `setup` and managed as Tauri state; `app_info.channel` tells Studio (`stable` | `beta` | `dev`, the e2e build answering as the product it plays).
- **The update check follows the line.** Stable reads `/releases/latest`, which GitHub never answers with a prerelease — exactly what 1.0.2 did, and its JSON is 1.0.2's (`stableNewer` is skipped when absent). Beta reads `/releases?per_page=20` and takes the newest by semver, prereleases included; **while it runs a prerelease** it also reports `stableNewer`, and Studio says *questiongame 2.0.0 is out* instead of the beta notice. A Beta running a plain version hears one message, not two. What a release *is* comes from its tag, never GitHub's `prerelease` flag.
- **What's new orders by SemVer** (`compareVersions`): `2.0.0-beta.2 < 2.0.0-beta.10 < 2.0.0`, build metadata ignored, an unreadable version lowest and never a throw. `crates/app/tests/fixtures/versions.json` is one ascending list both the TypeScript and the Rust `semver` tests read, so the two sides cannot disagree. A stable release's entry is written for stable users and summarises its betas.
- **Publishing is per tag** (`scripts/lib/release-route.ts`, run as the test job's first step): `vX.Y.Z` builds questiongame and publishes a normal release; `vX.Y.Z-beta.N` adds `--config crates/app/tauri.beta.conf.json` and publishes a GitHub pre-release named *questiongame Beta*. Anything else — `-rc.1`, `v1.0`, a leading zero, a tag that does not name `package.json`'s version — is refused before a build starts. *Run workflow* has a `channel` input and builds either without publishing, whatever the version; the installers are kept on the run as `questiongame-<channel>-<os>`.
- **Versions are bumped by command, never by hand**: `npm run version:stable [-- patch|minor|major]` on `release/1.x`, `npm run version:beta` on `main` (`X.Y.Z-beta.N` → `N+1`; the one-time move off a stable base is `-- --start X.Y.Z`, to `X.Y.Z-beta.0`). It refuses the wrong branch, a dirty tree, and a version without notes in every language; writes the four version files (`Cargo.toml`'s `[workspace.package]` line only, `tauri.conf.json`, `package.json`, `bundle.rs`'s assertion), refreshes both lock files and the map, runs typecheck and the bundle test, and commits `Version X`. A failing check or hook puts the tree back and commits nothing. **It never tags and never pushes** — it prints the tag, and publishing is the maintainer's word. Arithmetic is `scripts/lib/version.ts`; the git side is `scripts/lib/bump.ts`, tested against a throwaway repository with a bare remote.
- **Which branch.** `main` is the beta line; `release/1.x` is stable, cut after P13.0 so it carries everything above and none of Beta itself. Stable fixes land on `release/1.x` and are **merged** (not cherry-picked) forward into `main` after each stable release; conflicts are resolved on `main`. `main` moves to `2.0.0-beta.0` when workspaces start.

## questiongame Beta (P13.1)

- **A fourth identity**: `org.questiongame.beta`, product name *questiongame Beta*, its own icon (the stable one with a **BETA** band, `crates/app/icons/beta/`, generated from `source.svg` with `npx tauri icon`). `tauri.beta.conf.json` changes exactly the identifier, the name and `bundle.icon` — `tests/identity.rs` holds that, and that the base config names icons nowhere else, so the Beta installer cannot keep stable art. `npm run build:beta` builds it locally; a dev server refuses it (`identity::check`).
- **Beta never writes the stable folder — not one byte, not one new file.** SQLite never opens the stable library where it lies: `stable_copy.rs` byte-copies `questiongame.sqlite3` and any `-wal` a crash left through read-only handles into `stable-copy-<pid>/` inside Beta's folder, and `catalog::compact_copy` compacts that copy with `VACUUM INTO`. A read-only open in place would still have created `-wal`/`-shm` beside a show's library. The tests snapshot the stable folder (bytes, mtimes, listing) around every path, success and every fault stage alike.
- **A running stable app refuses the copy**, and the copy holds stable's lock while it runs: a shared lock on `questiongame.lock` through a read-only handle (which writes nothing), held until the copy returns, so a stable app started mid-copy is told it is already running instead of writing under it. A lock file that does not exist is a stable app that never ran, and is not created; one that exists but cannot be opened (an ACL, a backup tool's handle) counts as running — the check fails closed. A stable library newer than this Beta is refused before anything is written.
- **Only two files may name the stable folder**: `identity.rs` and `stable_copy.rs`. `tests/stable_folder.rs` greps `crates/app/src` (comments stripped) and fails on a third.
- **The copy is an ordinary upgrade.** `beta_copy_stable_library` checks the Beta library is empty (no operator, team, domain, question, asset, recipe or Play, archived ones too, and no Play loaded), copies **without the host lock**, then under the lock re-checks, swaps the compacted file in place of the empty boot-time library (dropping the connection first — Windows will not replace an open file) and reopens it through `Host::open_installed`: backed up into Beta's `backups/`, stamped, and *What's new* starts where the stable library had got to. The empty library is **set aside, not deleted**, until the copy has opened; if the copy will not open, that same file is put back and reopened, with the welcome still to come — Beta never carries on over an in-memory library whose work would be lost at exit. One copy runs at a time (`CopyInFlight`; a second is `beta.copy_running`): two would share the copy file and the temp folder. `beta.welcome_seen` is written by *Start empty* and by a copy; the welcome shows only on an empty library, so a crash between the swap and that row cannot offer a copy over work.
- Refusals carry their own codes (`AppError::Beta`): `beta.not_beta`, `beta.library_not_empty`, `beta.stable_running`, `beta.no_stable`, `beta.copy_failed`, `beta.copy_running`. Studio's welcome reads them inline (`05_STUDIO_DESIGN.md` §19).
- **The e2e build plays Beta** with `QUESTIONGAME_E2E_CHANNEL=beta`, and copies from `QUESTIONGAME_E2E_STABLE_DIR` — honoured only by the e2e identity, only for an absolute folder that exists and is not named `org.questiongame.desktop`.
- Still manual: installing *questiongame Beta* beside *questiongame* from a build-only run on Windows and macOS, and that uninstalling one leaves the other's library.
