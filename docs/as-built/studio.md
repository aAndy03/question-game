# Studio as built

`apps/studio`: the shell, Control, Screens, Settings, health, Statistics. The rules here are binding; `CLAUDE.md` points here instead of carrying them.

## The Studio shell as built (`apps/studio`, P7)

The design file is `docs/v1/05_STUDIO_DESIGN.md`; this is the part a later phase must not undo.

```text
host/     host.ts (command/on over an injectable HostTransport) · types.ts (wire shapes,
          mirrored from the Rust serde attributes) · queries.ts (TanStack Query keys + hooks,
          catalog/recipe/settings/monitors/plays only) · playState.ts (play-state as a
          useSyncExternalStore store) · commands.ts (useHostCommand: a refusal becomes a
          notice) · bridge.tsx (the one event subscriber) · fake.ts (in-memory host, the
          second adapter) · devFake.ts (`?fake` on a dev URL)
chrome/   nav.ts (typed route stack, back/forward, guard) · chrome.ts (sidebar, theme,
          grid|table per tab — persisted per operator) · notices.ts (§14 owner) · theme.ts
copy/     every operator-readable string
atoms → molecules → organisms → templates → pages   (eslint-enforced, one way)
```

- **Three stores, three jobs, and none of them is the Play.** TanStack Query holds catalog reads and is invalidated by `catalog-changed` / `recipe-changed` in `bridge.tsx` — no component refetches after a write. `play-state` is `playState.ts`, read with `usePlayState()` by organisms and pages. Zustand holds chrome; `chrome.test.ts` fails on any Play-shaped key. The tests behind the P7 exit criteria are `host/bridge.test.tsx`, `host/queries.test.ts` and `chrome/chrome.test.ts`.
- **A subscription is released, always.** Tauri keeps a JS listener registered on the Rust side until `unlisten` — a reload does not clear it, while the callback ids live in `window`, which a reload does clear — so a leaked subscription becomes `[TAURI] Couldn't find callback id …` on every emission, ten a second under the show loop. `host.ts` tracks every live `on()` and releases them on `pagehide`; `bridge.tsx` holds a `live` flag because `listen` resolves after StrictMode has already unmounted the first effect. Never push an unsubscribe from inside a `then` without one.
- **The active operator is host truth** (`settings_get.globals.active_operator_id`, written with `settings_set_global { key: 'active_operator_id' }`). The chrome store keys its per-operator document off it. Pin gating landed in P10.
- **`OperatorState.recipeId`** is how Studio knows which recipe a Play runs. The Game page freezes itself when that recipe's Play is `playing|paused`; the top bar names it.
- **Every interactive atom takes `disabledReason`** and renders it as a tooltip on a still-visible control (§4.2). `SettingRow` turns the host's `disabled` entry into that text with `disabledReasonText`; nothing recomputes an interlock.
- **A refused command is a notice, never a toast.** `useHostCommand` routes `CatalogError::Invalid`'s `<path>: <reason>` to the field with that path (`noticesAt`); `block` severity opens the dialog; the rest go to the collector and the status bar. **An addressed error is still heard from anywhere** (P12.8): the status bar shows the newest error of any surface, the collector names its place (`gameSectionOf`) with *Show*, a refused `play_load` opens the collector (`openCollectorOnRefusal`), the Game rail marks the section, the same refusal replaces itself instead of stacking, and a write the host accepts clears what it answers (`answeredBy`). **A library write can answer a Board refusal too** (P12.12, `answerFromLibrary`): a restore clears the refusal naming that row exactly; an edit (re-grading the twin, finishing a question) asks the host's `rules_preview` and clears the recipe's Board refusals only if it no longer reports a shared difficulty or an incomplete question — never a false all-clear. Since P21.3 the collector is the status bar's popover (▸ The smaller scale).
- **Editors are `useDraft` + `useDirtyGuard`** (one form state, dirty by structural comparison, a nav guard until Save / Discard / Keep editing), with `EditorFooter` pinned inside the scroll column. **The guard reads `draft.isDirtyNow()`, not the rendered flag**: an editor saves and navigates in one act, and React has not re-rendered in between — reading the flag raised "unsaved changes" *after* the row was written, and answering Save ran the save body twice. For the same reason a **new** record's blank is minted once and never re-derived from a query: the second save landed on a draft the refetch had reset. An organism never imports a template — that is a lint error — so editors render their own `PageHeader` and footer and the page wraps them in `RecordPageLayout`.
- **Organisms may not import `@/templates`**, and atoms/molecules may not import `@/chrome`'s nav or host anything. `LibraryList` takes `RecordView` rows; each page maps its entity to that shape once.
- **Icons are generated** (`npm run studio:icons` → `atoms/icons.generated.ts`) from the keys in `atoms/icons.ts`; there is no icon runtime and no `@iconify/react`. Calligraph is imported only by `packages/text/src/studio.tsx`.
- **Fields on panels:** `studio.css` gives fields a hairline edge and, in dark, a lifted background — `var(--surface-secondary)`, not a copied literal, so it follows the ramp. Do not "restore HeroUI defaults" here — the shipped dark theme makes an unfocused input on a surface invisible.
- **The dark theme is dark gray, and its values live in `globals.css`** (P20): HeroUI's near-black page (oklch 12%) under every tab cost contrast, so the whole ramp moved up together — background 24%, surface 28.5%, fields and secondary surfaces 32.5%, overlays 30.5%, separators 33%, borders 37% — and each layer still steps above the one under it; muted text and placeholders went to 73% to keep their contrast on the lighter panels. Move a dark value and its neighbours move with it. Light mode and Stage did not change.
- **Toasts are Sonner** (`chrome/toast.ts`) and only for transient, action-free feedback (saved, restored, loaded into Control, layout reset). A notice with actions, a `targetPath` or `block` severity is never a toast.

## The Control tab as built (`apps/studio`, P8)

- **The Viewer is the real Stage in an iframe** (`/stage/?viewer`), fed the stripped `PlayStateForStage` over `postMessage` (`packages/contract/src/viewer.ts`). Stage's `viewerHost()` is its third host adapter and **never acks**: the Stage window acks the overlay queue, the Viewer only reports node rects. Hit targets (`HitTarget`) are Studio DOM over the iframe, mapped node → command by the table in `05_STUDIO_DESIGN.md` §10.2. Do not put anything interactive in Stage's tree for the Viewer's sake — `viewer.test.tsx` diffs the two trees.
- **A resolved session is not a live one.** `play.session` is only ever *replaced* — by the next `QuestionIssued` — never cleared, because Stage goes on drawing the question with its outcome. `session !== null` is therefore true from the first question to the end of the Play, and reading it as "a question is in progress" locked the operator out of `choose_domain` for the rest of the show (2026-09-07). `host/session.ts` spells the host's own rule (`liveSession` · `isSessionLive` · `canChooseDomain` = issued **and unresolved**); the Viewer's domain targets, the number chords and the Action Panel all read it, and `crates/host/tests/demo_scenarios.rs` checks the predicate against the command at every beat of a turn.
- **`play_unload` is the way out of Control**, legal whenever a recipe is loaded. Anything not already closed is closed on the way out — a Play that vanished while `playing` would be resumed at boot, and a `loaded` row is reached by no cleanup — and `discard` deletes that one Play's log (`CatalogService::play_delete`), the only hard delete besides `wipe_plays`. **The Stage window is never touched**: it stays on its display and goes back to Idle, because `stage_state` is total (`stage::empty_game` when no Play is loaded) and `main`/`stats` get `null`.
- **A ring row says what it is** (`ringRole` in `host/ring.ts`): `holder · next · override · reveal-first · served · inactive · solo · closed`. The Action Panel and the Viewer both label from `RING_ROLE`, so "next in order" and "out of order" read the same wherever the operator meets them.
- **Control draws one phase at a time.** `controlPhase` (`host/session.ts`) is `ready · question · resolved · handover · standings · ended`; the Action Panel renders transport, that phase's one block, then the token rows. Disabled-with-a-reason is for an illegal control *within* a phase (§4.2); a control belonging to another phase is hidden, because the host would refuse it. `standings` is what a completed Play gets — *Reveal next place* (the lowest unrevealed rank, ties sharing one), *Show final leaderboard*, and Restart — and it replaced the spent question controls that left the operator stuck at the end of a show.
- **The Action Panel offers the next question.** One button per domain, from any screen: a correct answer leaves the token where it is and the usual next act is another question, so the operator is not required to be standing on ChooseDomain. Before it existed, a domain card in the Viewer was the only door.
- **One command, three call sites.** Hit target, Action Panel button and chord all call `useHostCommand().run`. `useControlHotkeys` is mounted by `ControlPage` only, `ignoreInputs: true`; chords come from `settings_get.globals.shortcuts` with `HOTKEYS.defaults` as the fallback.
- **The ring is derived, never stored** (`host/ring.ts`): history / current / future from `turnsTaken` and `roundIndex`; a drop is legal only future→future and `reorderedRing` builds the full order for `reorder_ring`. `RingRow` carries the nine spec variants; the variant is the whole visual state.
- **The mosaic is `react-mosaic`** restyled by `packages/design-studio/mosaic.css`; the tree is chrome, persisted per operator in `chrome/control.ts`. `MosaicPanel` measures its box and hands each panel a density; panels branch on it and never scroll horizontally.
- **Timeline** reads `play_events` through a Query keyed on `(playId, eventCount)`; the tick's `eventCount` is what refreshes it.
- *(History — `LibraryList` no longer uses TanStack Table since stable 1.1; the rule below still holds for any memoizing library.)* **`useReactTable`'s `data` must be referentially stable, including while it is empty.** TanStack Table memoizes the core row model on the identity of `data`, and every change queues `resetPageIndex` on a *microtask*: a `setState`, a re-render, and — with `rows ?? []` — a new array, so another change. Nothing in that cycle is an update React would refuse as too deep, and it never yields to a task, so the host reply that would have filled `rows` never arrived: Studio froze on every Archived toggle whose list was empty, at ~120 commits a second (2026-09-08). `LibraryList` uses one module-level `NO_ROWS`; `LibraryList.test.tsx` renders the undefined-rows list three times and asserts three commits. The same rule holds for any array or object handed to a memoizing library from a render.
- **`?fake&slow=<ms>` answers every command a task later**, the way the real IPC does. A page that only stays healthy because the fake answers in a microtask is exactly the page that freezes in the app; test shell work with it before calling a loop "does not reproduce in a browser".
- **A panel wraps before it abbreviates, and steps down last.** `MosaicPanel` measures its tile and hands the panel a density, but a step down *removes information*, so the steps sit low (300px / 180px) and both strips wrap instead: `ScreenStrip` is a **detached, wrapping** `ToggleButtonGroup` — never `fullWidth`, because seven labelled screens fit no row the mosaic offers, and the tile clips horizontally by design (§8) — and `OverlayStrip` keeps every pill's whole label. `RingRow` keeps the score at every density. The render prop also gets the measured box, which is how the Game panel steps its rows down when the *roster* outgrows the tile's height rather than its width.
- **Armed states** (Reveal & pass, restart, abandon) are component state and reset on unmount; nothing on Control is remembered except the layout.

## The Screens tab as built (P9)

- **`recipe.layout` has a shape now**: `packages/contract/src/layout.ts` (`version · decor · nodes · screens`); `parseLayout` is the validator and drops anything foreign. The host still stores it opaquely and passes `{ nodes, screens }` through as `play-state.layout` (`PresentationService::set_layout`, next to `set_decor`; both are set at `play_load` and `recipe_set_layout`).
- **Stage applies overrides in one place**: `apps/stage/src/layout/apply.ts` writes inline styles onto `[data-node-id]` elements and re-applies after re-renders. Offsets are the `translate` property — never `transform`, which GSAP owns. Do not add per-component style merging; add a node id and the applier covers it.
- **The canvas is the Viewer again** (same iframe, same protocol) fed a preview Play from `host/previewPlay.ts`; `NodeHandle`s are Studio DOM and never enter the saved document. Decor nodes get no handle — the dials tune them.
- **Auto-save** is one `recipe_set_layout` per 400ms debounce, one `rev`; `LayoutEditor` keeps the draft dirty until the host confirms.
- **DialKit is not used** (it needs its own panel to render); dials are `SliderField`.

## Settings, first run, notices, audio, health as built (P10)

The design is `docs/v1/05_STUDIO_DESIGN.md` §12; §12.11 records the departures. What a later phase must not undo:

- **`run` is the payload, `run.ok` is the verdict.** Most §13 commands answer `()`, which reaches the webview as `null` — the same `null` `useHostCommand` returns for a refusal. A `()` command therefore asks `run.ok(name, args)`; `await run('play_load', …) !== null` is always false. Commands that answer with a value (`wipe_plays`, `catalog_upsert`, `catalog_seed_demo`, `recipe_set_layout`) still read `run(…)`.
- **First run latches in `App`.** The operator step creates and activates a row, so the condition that raised the wizard goes false mid-flow; `App` keeps the wizard up until `FirstRunPage` reports `onDone`. Do not "simplify" it back to a derived boolean — the sample and defaults steps disappear.
- **The Demo lives in the host** (`crates/host/src/catalog/seed.rs`, `seed_demo` with `missing` | `overwrite`, rows `origin = seed`), and replaced P6's dev-only `crates/app/src/demo.rs`. **Restore Demo** in Settings asks `catalog_seed_status` first; an edited seed row is only overwritten after a confirm.
- **A pin is hashed in the host and nowhere else** (`crates/host/src/operator.rs`, argon2id). Studio sends the digits as typed; the row carries an opaque `pin_hash`. A gated command (`wipe_plays`, `uninstall_data`) refuses a loaded Play **before** it looks at a pin — the pin is not what protects the show — and no gated command can touch a live Play.
- **Audio's interface is the cue key.** `apps/stage/src/audio/port.ts` has two adapters — `howlerAudio` on the Stage window, `silentAudio` in the Viewer, the fixture strip and tests — and cues are derived from a play-state diff (`cuesFor`). `feat.audio.synth` is a switch with nothing behind it: `no-synth.test.ts` greps the Stage tree for the synthesis APIs, so keep the placeholder pack generated offline by `scripts/audio-placeholders.ts`.
- **Health is chrome, not Play.** `crates/host/src/health.rs` is silent until there is something to say and pairs every item with at least one action; `chrome/health.ts` keeps only the headline for the status dot, and the items are ordinary §14 notices, replaced wholesale on each report.
- **`settings_get.disabled` is the only source of a disabled reason**, in the fake host too — Studio renders it and never recomputes an interlock.

## Health, and reports that can be withdrawn (P11.8)

- **A retired `Howl` may not report.** `unload()` on a `Howl` that is still preloading aborts its decode, and Howler delivers that through `onloaderror` as *"Decoding audio data failed"* — from the callback, indistinguishable from a file that is not there. Two things retire one deliberately: `dispose()`, and `load()` replacing a cue whose file changed. `howlerAudio` keeps an **epoch per cue** and reports only for the Howl that is still the cue's own — an epoch rather than a flag cleared around the call, because Howler may deliver the error long after `unload()` returned.
- **Why it mattered:** `main.tsx` renders under `StrictMode`, `howlerAudio` starts all eight preloads *during render*, and React mounts `useAudio`'s effect and immediately unmounts it — so every Stage open produced eight `audio_missing_cue` reports in one millisecond, and the second mount then loaded them all and played them correctly. The log shows exactly 8, once per open, 13 times.
- **Every health input needs a reverse.** `HealthState::missing_cue` only ever added, so one report latched a warn until the process ended — through `play_unload`, through closing the Stage window. Stage now reports `audio_ok` when a cue it had reported loads after all, and `cue_ok` drops it. There is deliberately **no** clear on `play_unload`: a cue file that really is missing is still missing, and hiding it there would be the same bug pointed the other way.
- **The status dot reads `report.status`; the collector renders only `collector` notices.** An `inline` health item (`health.audio_missing_cue` carries `.at("audio.cues")`) was in neither, so the dot went amber over a panel that said *No notices yet*. The collector now ends with a **"needs attention elsewhere"** line naming each place and offering *Show*; `inlineNotices` is the selector, `CHROME.elsewhereAt` the path → place table. Add a path there when a new inline notice is introduced.
- Still open: `audio_failed` (a *playback* fault — the file is present and the browser refused to sound it) is reported as `health.audio_missing_cue`, which reads wrong. One notice code, one line of copy.

## Statistics as built (P11)

The design is `docs/v1/05_STUDIO_DESIGN.md` §13. Statistics is a **projector**, and that is enforced on both sides:

- **One command, one document.** `stats_query` takes `{ filter, groupBy, metrics, limit }` and answers `{ rows, totals, playCount, turnCount }`. The same command feeds the Live tiles, the All-data table, the entity cards and every chart — there is no second stats verb, and no `StatsService`, because Statistics owns no state.
- **`crates/host/src/stats.rs` is a pure fold**, next to `play.rs`: `facts(events) -> [TurnFact]` (one resolved turn each, with the snapshot's names and difficulty) then `aggregate(facts, query)`. `CatalogService::stats_query` only decides which logs to read — SQL stays in `catalog/store.rs`. An **undone turn is not a fact** (the same inversion spans the projection uses), a metric with nothing to average is `None` **not zero**, and a rehearsal (one team) is excluded unless asked for.
- **Rows are relabelled from the catalog** (`relabel`): the fold labels a row as the Play knew it, and §12's "rename team → Statistics" is that one lookup. A row whose subject was archived keeps the Play's label.
- **Studio cannot write here.** No file under the Statistics surface imports `useHostCommand` — `pages/statistics.test.tsx` greps for it — and the host refuses regardless: `guard::STATS_COMMANDS` is the read-only list the `stats` webview may call.
- **The Statistics window is Studio, not Stage**: `studio/index.html?stats`, the same bundle and tokens, the Statistics page alone. **The operator opens it and nothing else does** — `stats_window { open }` is the only door, `stats.monitor_id` says where it would go and `stats.fullscreen` how, and a display coming back never re-opens a window that was closed. Whether it is up is window state (`monitors-changed.statsOpen` → `chrome/windows.ts`), never a setting. Stage's display is refused; unplugging its own closes it with a notice and touches no Play. It is addressed like any other webview: `emit::play_state` sends it the `main` shape and the two catalog events, and it listens as `stats` (it used to see everything only because a bare `listen()` is an `Any` listener).
- **Never touch a window or the display list while the host lock is held**, and the rule is now enforced: `AppState::lock` hands back a `HostGuard` that counts itself, and `state::assert_unlocked` — called by `windows::ensure_stage` / `open_stats` / `close_stats` / `open_studio` / `apply` / `place` and by `monitors::list` / `physical_origin` — is a `debug_assert!`, so a violation is a panic naming the call site instead of a hang. Every one of those pumps the OS message loop, and pumping it dispatches whatever IPC the webview has queued; if that is one of the **synchronous** commands (`get_state`, `settings_get`, `health_get`, `monitors_list`, `catalog_seed_status`) it runs on the *same* thread and calls `lock()`, which is a plain non-reentrant `Mutex`. The app then waits for a guard only that thread can release: no repaint, no input, not even a reload, and no second thread to blame in a dump. `windows::refresh` therefore takes `&AppState` rather than a guard — read the OS, decide under one short lock, then act (2026-09-08; it had been violated by `monitors_list`, `stage_set_monitor`, `play_load` and the monitor watch).
- **ECharts is imported in exactly one file** (`molecules/StatsChart.tsx`), themed from the Studio CSS variables; a test pins that. EvilCharts is not installed.

Statistics is a picture first (P20; design `docs/superpowers/specs/2026-10-22-p20-interface-pass-design.md` §9):

- **ECharts is handed rgb, never oklch.** HeroUI's tokens are oklch and ECharts parses colour strings itself — its hover highlight works from the colour it was given — so an oklch fill became an invalid colour on hover and the hovered bar vanished. A theme colour is resolved on the chart's own element and converted before ECharts sees it; a `var(--…)` that resolves to nothing is the accent. A team's Stage theme colour (`var(--state-…)`) is no Studio token at all: Live leaves it out and that line takes one of the chart's own colours. Axis text is `--muted` (it read `--foreground-muted`, which does not exist, so it was always `#666`).
- **The option is a memo over the props**, the colour, total and roster records keyed by content: they were rebuilt on every render and sat in the effect's dependencies, so the chart redrew on every render. `animation: false`; a null is never a zero (a ranking leaves the row out, a line or a band leaves a gap).
- **`StatsChart` has a closed `kind`** — `bars · ranking · verdicts · timeline · bands · race` — and draws rows in the order the host sent them (days by date, bands easy to hard), except `ranking`, which is a sort (the top 12; the rest are in the table). `verdicts` finds correct, partial and incorrect by metric name. All data reads the kind off the answer's `groupBy`, not the filter bar, so the picture stays that of the rows it draws while the next answer loads.
- **Live's leaderboard is the contract's `leaderboard(play)`**: the scoreboard's order and its ranks (`1, 1, 3`) from play-state, each team's by-team `stats_query` row looked up by id, a team the log has nothing for yet a row of em dashes. Never re-sort it by a stats column — before P20 it was the host's order by the first metric, turns, so a team with more turns led a team with more points.
- **The race is drawn backwards from the scores.** Live's ledger is capped (`LEDGER_ROWS`, the last 60 turns), so each line ends at the team's play-state score and each earlier point takes off what that turn paid. When the ledger accounts for every point the lines start at 0; otherwise the axis counts on from the turns before it and the note says these are the last ones. Drawn forward from zero, a long Play's lines would start mid-show at nothing.
- **A hidden filter still says it is there.** All data keeps Columns, *Include rehearsals* and *All workspaces* behind *More options*, and the closed button counts what inside it is not at its default (`More options · n`; rehearsals, all workspaces and changed columns once each). Tables and cards show 50 rows (`STATS_CAP`), then *Show all n*. A tile or summary figure is read by metric name; one the log cannot give is an em dash, never a zero.
- **The Statistics window never calls `workspace_list`** — the guard refuses it to `stats` (`app-shell.md`). The line under the title reads the workspaces from the cache (`useKnownWorkspaces`, `enabled: false`), which the sidebar's read fills in the main window and `workspace-changed` in this one; beta.5's line had asked through `useWorkspaces()`. The window's column is full width (`SettingsLayout width="full"`); the tab keeps its bounded one.
- **Live draws one pair that agrees** (`useAgreeingPair`). Play-state moves the moment a reveal lands; the stats answer is one IPC behind and shown as placeholder data meanwhile, so drawn together the race ended at new scores over an old ledger and the leaderboard ranked new scores beside old points. The last answer that was not placeholder is kept with the play-state it was asked for and drawn until the next arrives. Another Play's pair is never held, and a failed answer forgets the pair: TanStack offers the answer before the failure as the next count's placeholder, and holding it would bring back what Live had let go.
- **A team's colour in Statistics** (`teamColours`): what the operator wrote is the team's, always; a Stage state token is drawn in its Studio meaning (`STATE_IN_STUDIO`: incorrect → danger, correct → success, info → accent, leader and accent → warning) — the shipped Demo's Red is `--state-incorrect`, and it had come out blue — unless an earlier team already shows that colour; anything else takes the first of `SERIES_TOKENS` no other team shows, compared as painted. `SERIES_TOKENS` (exported by `StatsChart`) is the chart's own palette too: one list, one order.
- **`toRgb` paints on an `OffscreenCanvas`, else a document canvas** — WKWebView before Safari 16.4 (macOS 10.15, which Tauri 2 supports) has no `OffscreenCanvas`. Under jsdom it never asks for a 2D context (jsdom prints an error when asked) and passes the colour through.
- **A ranking of a lock time ranks the fastest first** (a `milliseconds` metric sorts ascending), and value axes format with `formatMetric` for ratios and times. **The verdicts stack draws only the verdicts the answer carries**, and All data's query adds `partial` whenever it will draw the stack, keeping it out of the table unless ticked. **Show all** belongs to the answer it was pressed on: a new answer is capped again.
- **The fake answers `stats_query` by metric name** (`fake.statsBy` per dimension, then `fake.stats`; `byMetric`): a value belongs to its metric, never to its position, and Live asks three dimensions at once — one canned answer for all of them is a table of teams under a Domain heading.

## questiongame Beta in Studio (P13.1)

- **The welcome comes before first run and latches like it** (`App`: `welcomeDone`), and until `beta_welcome_get` has answered `App` renders nothing — otherwise first run latched underneath it. A stable, dev or no-host Studio is "settled" at once.
- **The update check and *What's new* wait for it** (`useUpdateCheckOnStart(enabled)`, `useWhatsNewOnStart(enabled)`): a copy replaces the library, and the notes belong to the one it brings. Both still ask once per process.
- **The welcome calls `command()` directly**, not `useHostCommand`: a refusal is said inline because the shell and its collector are not up, and the page reads the code (`beta.stable_running` → *Try again*; `beta.library_not_empty` → done). After a copy it invalidates every query — a different library.
- **The chip reads `app_info.channel`**, never `build`: the e2e build playing Beta answers `build: "e2e"` and `channel: "beta"`.

## Workspaces in Studio (P14.2)

The design is `05_STUDIO_DESIGN.md` §21; the host half is `host.md` ▸ Workspaces.

- **A switch resets, it does not invalidate**: `receiveWorkspaces` (the bridge, on `workspace-changed`) resets every workspace-scoped query — library, search, games, Plays, statistics, the Demo's status, settings, the rules preview — so no list ever shows the last workspace's rows under the new one's name. Monitors, paths, the build and the welcome are kept. Query keys do **not** carry the workspace: the reset is the one place that knows, and a key that forgot the workspace would be the leak the reset exists to make impossible.
- **The name gate latches like first run** (`App`: `namedDone`) and sits between the welcome and first run; its mode (*create* / *name*) is "no operator and no active one", the same test first run uses.
- **Operators are global** in the host and in the fake (`inView` lets every `operator:` key through) — a switch that hid them looked like the operator had been signed out.
- **The fake keeps a home per row** (`homes`, `recipeHomes`; a row seeded without one is the first workspace's) and runs the workspace, transfer and propagation commands with the host's refusals, so a shell test never passes against a fake that cannot say no. `?fake&unnamed` (and `?fake&firstrun`) open on an unnamed workspace.
- **No shared library since beta.2**: no *Where* filter or grouping, no Shared chip or globe, no shared counts; the transfer menu is *Copy or move…*. *Copy to…* of questions asks *Bring their domains* (on) and names, from the preview, the domains it joins (`joined`) or creates.
- **A switch leaves nothing of the old workspace** (beta.2): Screens and Statistics (Live, All data) are keyed on `useCurrentWorkspaceId()` (a cache read — the Statistics window may not ask `workspace_list`), so the old game and filters go; `receiveWorkspaces` resets when it had no previous value (the Statistics window), and the bridge then clears Back/Forward and drops notices whose target is a row (`dropRowNotices`). The Statistics window's title names the workspace (`windows::stats_title`).

## Domain groups, tags, bulk edits in Studio (P15)

The design is `05_STUDIO_DESIGN.md` §22.

- **The default grouping is computed** (`questionsSpec` → `defaults.group = 'groups'` when the domain has groups); a grouping the operator picked is remembered per tab and wins, as in 1.1.
- **`tag_list` sits under the question key** (`['catalog', 'question', 'tags']`), so every question change refetches it and a workspace switch resets it.
- **Every Studio site that rebuilds a `DomainMember` carries `groupId`** — the domain pane saves what the host sent, and the question editor writes its group pickers through the same membership loop.
- **A filter value that is no longer an option goes** (`useListView`): a deleted group, a renamed tag, or another domain's groups would otherwise empty the list behind a chip that names nothing. Options still loading (an empty list) prune nothing.
- **A field that commits on blur must not eat a click**: `TagField`'s offered tags keep focus with `onMouseDown` → `preventDefault`, and `EditorFooter`'s Cancel sits in `data-keep-draft`, which the field's blur skips. The bulk dialog keys its preview by the edit it was asked for; *Apply* on a stale key re-asks, then writes (waiting instead disabled *Apply* under the click — e2e, twice).
- **Group dialogs stack**: the Groups and Manage tags dialogs stay open under their Rename / Delete (closing and reopening the parent flickered and threw focus back to the toolbar). `useGroupEditing` is shared by the Groups dialog and the group header menu.
- **The fake host** keeps domain groups in a map of its own (never on the stored row, as the host ignores `groups` on a save), and cleans tags as the host does.

## Copy, import, the editor in Studio (beta.3)

The host half is `host.md` ▸ Copy, import and refusals.

- **The question editor writes once**: the question and every domain whose membership it changes go in one `catalog_upsert_many` — or, on *Also update copies*, in one `catalog_upsert_propagating` with the domains as `with` — so a refused membership leaves no saved question (and no updated copy) behind, and no "Question saved". *Also update copies* is asked (`usePropagatingSave.decide`, which asks without writing) only when the body changed — stem, options, difficulty, explanation, media, tags (`sameBody`). A preview the host refuses is a notice and the save stops: saving without asking would leave the copies behind. A second press of Save while the question is open does nothing.
- **Twin names are a field description, never an error** (`host/twins.ts`: case and spaces folded): the team, domain and game name fields say "Another team in this workspace is named Red.", against active rows of the workspace other than the one edited. The transfer dialog says "Club already has a team Red. Both will be there." from `TransferReport.twins`.
- **Archive confirms name the games**: `useArchive` asks `referenced_by` once with every picked id and shows the host's sentence (`CONFIRM.referencedBy` / `referencedByMany`); the confirm is armed while the answer is pending and when something uses the rows, and only the newest request's answer is kept.
- **A theme colour is a swatch**: a team colour that is a token (`var(--state-incorrect)`, the Demo's) shows as a checked swatch labelled *Theme colour*; the hex field (*Colour code*, its own name beside the *Colour* group) is empty with `#RRGGBB` as its placeholder. Only a `var(` value is a theme colour: anything typed stays in the field, with or without its `#`. Found on the real app.
- **The import preview** adds, per row, *In …* (`landing`), *Tags: …* and *Repeats "…"* (`duplicateOf`) or *Repeats row n of this file* (`duplicateRow`); a duplicate's status reads *Duplicate*, since it may repeat a row of the same file. A row in no domain says so once, as a gap.
- **Twins are not re-checked on Restore**: restoring an archived row beside an active one of the same name says nothing; the next edit of either shows the note. A soft warning, by design.
- **Dialog footers wrap** (`studio.css`: `.alert-dialog__footer`, `.modal__footer`), and *This row has copies* is `md`: its three actions spilled out of the frame at `sm` (the maintainer's beta.2 screenshot; `workspaces.e2e.ts` now asserts every button sits inside the dialog).

## The interface pass in Studio (P20)

The design is `docs/superpowers/specs/2026-10-22-p20-interface-pass-design.md`; the plan and test list (with its pinned decisions) is `docs/superpowers/plans/2026-10-22-p20-interface-pass.md`. It was checked over the maintainer's Beta library (1,050 questions, 15 domains, a 569-question game) and over a first evening. Statistics is under ▸ Statistics as built; the dark theme under ▸ The Studio shell.

- **The type roles are `@theme static`** (`packages/design-studio/tokens/theme.css`). Tailwind v4 emits a theme variable only when a utility uses it, and `Text` reads the `studio-*` roles from an inline style Tailwind never sees: declared `inline`, every role but the label's resolved to nothing and fell back to the inherited 16px, so from P7 to P20 titles, headings, body and captions were one size while labels were 12px (a setting's name smaller than its description). jsdom applies no CSS, so no component test could see it; `packages/design-studio/src/tokens.test.ts` compiles the theme with Tailwind and fails on any variable a `studio-*` variant reads that is not emitted. A new role goes in that block (`studio-subheading`, 14px medium, is a name inside a section).
- **`ListArea`** (`templates/`) draws every library list: the toolbar on its own row, then the list and the opened row's `DetailAside` side by side. On Questions the aside started level with the toolbar and took its width, so *Active · Archived · All* wrapped under it and the list jumped each time a row opened or closed; below 1280px the aside covered the toolbar. `ListToolbar` keeps View · Status in a right cluster that does not wrap, so Status stays top right at every width; DOM order is unchanged.
- **The selection strip is always mounted** (`BulkBar`, `data-bulk-strip`) on a list with bulk actions: quiet at 0 (a dashed hairline, "0 selected", nothing to press, `data-bulk-idle`, no `role="toolbar"` — a toolbar offering nothing is noise to a screen reader), the bar once something is ticked. It used to mount on the first tick, so the list jumped 56px on a tick, on *Clear* and on a filter that cleared the selection, and a second click in the same place ticked the page. It is one element at 0 and at n (`LibraryList.test.tsx` asserts the same node); never return `null` at 0. Grid view gets the *Select all* tick through `page`; table view's header keeps its own. **Since beta.8 that tick reaches every page** (every matching row; unticked, it clears) and the strip's *Select all {n}* button is gone — it was most of the strip's congestion, and the tick was where operators looked. **The strip never scrolls**: the actions are `overflow-hidden`, and when they do not fit `BulkBar` measures it (a layout effect and a `ResizeObserver`, unsqueezed first so words come back as soon as they fit) and sets `data-squeezed` — every button with an icon becomes the icon, named by a `title` the strip adds and takes away again. The count and *Clear* never shrink.
- **Menus are sections** (`ActionMenu`, `renderMenuSections` for the hand-built bulk menus; titles from `MENU`). A section's id is `section:<id>`: React Aria keeps sections and items in one collection, and *Copy and move* (`copy`) holds *Copy to…* (`copy`) — a duplicate key. An item's `aria-label` is its label alone: the reason or note under it is a `Description`, and it had leaked into the item's name, while the e2e picks menu items by exact text. An empty section is left out with its separator; an item with `isDisabled` or a `disabledReason` is in `disabledKeys`.
- **`SortableList`** (`molecules/`, `@dnd-kit/react` sortable, as Control's ring) orders the roster, the Board's domains and a question's options (the editor's draft and the import row form). The drop writes once; the order shown is optimistic until the next `ids`, **compared by content** — callers build `ids` with `.map` on every render (the Board's when a pending flag flips), and compared by identity any re-render would drop the new order before the host answered (`SortableList.test.tsx` re-renders with rebuilt ids). `onReorder` answering `false` (a refusal) puts the old order back. The keyboard works on the `DragHandle` button: Space lifts, the arrows move, Space drops, Escape cancels.
- **Sortable tests drive the real dnd-kit**, not a mock. `test/setup.ts` stubs what jsdom lacks and dnd-kit calls — `document.getAnimations` (it finishes running animations before it measures a lifted row), `Element.animate` (it animates the drop and removes its placeholder when that finishes), `IntersectionObserver` (it watches which rows are on screen while one is lifted) — and `test/sortable.ts`: `stubRowLayout` gives each `[data-sortable-row]` a box by its index, because jsdom lays nothing out and the keyboard sensor finds the next row by geometry; `keyboardDrag` lifts, moves and drops by the handle.
- **A big Board opens closed**: more than 40 questions or more than 4 domains (`startsOpen` in `BoardSection`), with *Open all · Close all*; a small board opens. Fifteen domains of thirty-eight questions are a page of headers, not five hundred rows. An open row lists its questions in the walk the snapshot asks them in — effective difficulty, then id (`SnapshotDomain::new`) — whatever order they were ticked in. The domain rows are dragged into the board's order, which is the order the snapshot, and Stage's ChooseDomain grid, list them.
- **A game's folder and game tags are organisation, not the show**: Load, the snapshot and Stage never read them, so on the Game page Folder (`ComboField`) and Game tags stay editable while the game plays and only the name freezes. Every place writes them with `recipe_bulk_edit` — the Game page, the Games bulk *Edit…*, the row's *Organise*, the manager — never `recipe_upsert`, which is the name-and-rules write. A write still moves `rev` (`host.md` ▸ The interface pass).
- **The shell draws no lines and no bars** (P20.11, the maintainer's pick after trying both). The top bar, sidebar and status bar paint `--chrome` (the page's background) and every line the shell draws — `TopBar`, `StatusBar`, `SidebarNav` and its `ChromeLine`s, the Control (`ControlPage`, `MosaicLayout`) and Screens (`WorkshopLayout`) strips, `WizardLayout` — is `--chrome-line`, transparent. A new shell line uses the token, never `--border` or `--separator`: those were two greys at two heights, and the lines never met. Settings sits on the status bar's row at its size (`SidebarItem size="sm"` in an `h-7` row).
- **A hidden sidebar is gone, not zero wide**: the `nav` is `inert` and `aria-hidden` while hidden, or its own *Show sidebar* toggle stayed tabbable beside the edge's. The edge is a `button` (`data-sidebar-edge`) whose solid `--muted` bar shows on hover or focus only; a press is `setSidebar(DEFAULT_PREFS.sidebar)`. The hover peek (`peeking` in the chrome store) is gone.
- **Editors have no footer bar.** Cancel · Save are `EditorActions` in the `PageHeader`, and the header goes in `EditorColumns`' `header` slot: sticky, on `--background`, spanning both columns, so the buttons end where the content ends at any width (a header outside the grid put them at the window's edge on a wide window). The slot's `-mt-6 pt-6` assumes `RecordPageLayout`'s `p-6`.
- **A truncated `Text` cannot be hidden by a class**: `truncate` writes an inline `display: block`, which beats `hidden`, so `RecordRow`'s options and *also in…* note showed at every width. Responsive visibility goes on a wrapper around the `Text`. The options show from a `@5xl/list` list, not a window breakpoint.
- **Difficulty is `DifficultyChip`** wherever a question is listed (`Easy · 20`; `difficultyLabel` for an aria-label). On the Questions list it is `RecordRow`'s `badge`: in a table a fixed-width slot at the end of the title area, outside the chips container that hides below `@lg/list`, so the difficulty survives a narrow list; on a card the first chip. `columns.lead: null` drops the header's lead spacer when the rows have no leading mark. A `Chip` never wraps or shrinks.
- **`[data-density="compact"]`** (`studio.css`) sizes HeroUI's `.button` and `.select__trigger` inside it to 28px. Its rules are `[data-density] .button` — two classes — so they beat HeroUI's `.button--sm` and its `md:` variant whatever the order; the select also pins `line-height`, or the 14px text's line height left it 30px.
- **A disabled field keeps its width only if every wrapper round it is a block**: `DisabledReason block` is a `block` span *and* passes `block` to `Tooltip`, whose HeroUI trigger is an `inline-block` div — either one alone shrank a disabled slider to its 24px thumb (seen on the Beta library's Rules).
- **The list toolbar is a container** (`@container/toolbar`): from 48rem one row; below it the lead and View · Status take the first row and the tools the full width under them, by CSS `order` only so the DOM and tab order never change. Sharing a row with View · Status on a narrow list, each tool wrapped alone, four rows high.
- **Numbers in Statistics are grouped** (`formatMetric`: 81,550, as the Board writes points); a chart with nothing to draw is only its note (the box collapses to 0, the instance is already disposed); a manager with nothing in it is its `empty` state alone.
- **Import overrides belong to the text they were made on.** The dialog keeps edits by row index (1-based, as the host numbers rows) and skips as indexes, sent as `overrides: { edits: [{ index, row }], skip }`. `replaceText` drops the edits, the skips, the open row and the list state **in the same update as the new text**: an index from the old file names another row of the new one (the host refuses only an index that is no row at all), and clearing them afterwards in an effect sends one preview of the new text with the old indexes. A loaded file survives Esc and a press outside (`isDismissable={!hasText}`); *Cancel* drops it.

## Library views as built (stable 1.1, P13.2–P13.4)

The design is `05_STUDIO_DESIGN.md` §20. What a later change must not undo:

- **There is one list-view model and it is pure** (`host/listView.ts`): filter, sort, group and page are decided there and nowhere else. `LibraryList` draws a `ListPage`; it does not sort, filter or select. **TanStack Table is gone from `LibraryList`** — its row model was a second sort, its selection a second selection, and its page-index auto-reset was the P11.3 freeze. TanStack Virtual stays, for page size *All* over 200 entries.
- **Every tab is a `ListSpec`** in `host/listSpecs.ts`; a filter, sort or grouping is one entry there. Text is ordered by one collator (`compareText`: no case, no accents, numbers as numbers); a missing value sorts last both ways (`nullable`); a *No …* group says `last: true`.
- **`ListToolbar` is the one toolbar** (reversing §9's "not a component"): one component is how the order stays the same on every tab.
- **The session slice is `listState`**, not `listSession` — `chrome.test.ts` bans any key containing "session". It and `prefs.*.lists` are the only subtrees the banned-key walk skips (`isListViewKey`).
- **`setListState` writes nothing when nothing changed, and `setSearch` ignores the text it already has.** `SearchField` reports its text when it mounts; before both rules the first build looped (*Maximum update depth exceeded*) and would have sent the operator back to page 1 on every return to the tab.
- **Search is uncapped**: `useListHits` asks for as many hits as the list has, only once the list has loaded, and ignores TanStack's placeholder data so Best match never orders by an older search.
- **Studio's queries never pause offline** (`networkMode: 'always'`): every query is a call into the app's own host.
- `?fake` covers it all; the e2e spec `library-views` runs it on the real app with 120 extra questions (`e2e_library --more-questions`).
