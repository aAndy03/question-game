1. Short description:
A game of question and answers.

1.1 When? How? 
Competing teams and the game moderator can see the game presented on an external display, TV, monitor, projector etc. So this is the presentation or stage.
The stage is controlled by an operator in the app. The app allows the operator determine what's going next on the stage/presentation.
There is a game engine that owns the game itself. The stage presents the game through custom built SLIDES/SCREENS.

1.2 Who owns what?
The engines work layered.
To ensure everything works correctly we have to separate concerns to different engines. Every engine owns what it has to do. To ensure the engines work correctly we can introduce Layered Engines: 
(Layer 1) A single engine that owns it's own concerns 
(Layer 2) An engine that owns/manages/binds/operates two single engines. I imagine these facilitate the talking between the two engines
(Layer 3) An engine that owns/manages/binds/operates (layer 1) + (layer 2) + (layer 2) OR (Layer 2) + (Layer 2) + (Layer 2) + (Layer 1) OR etc...
(Layer 4) and so on....

(Layer 2), (Layer 3), (Layer 4) and so on have to ALSO manage their own states and metadata.


Also, for React follow the api/docs pattern. I think react uses Providers. and other things. make sure you follow the react 19 api docs.

2. How the game plays.
spec v1 for questiongame
the game rules and variables.
1. Teams [n number of teams]
2. Questions [difficulty]
3. Answers
4. Domains [questions]
5. Points [number]
The game settings, names, domains, questions, difficulty, answers, points and other variables (not yet included in this spec, but might be introduced in future) can be changed/are set before the game plays; 

The game is played in teams. The game follows a predictable order of the teams. 
The domains can be n number. They also can hold n number of questions. Each question has it's own set difficulty (as number between 1 and 100). Per domain, the difficulty progresses from easy to hard. Once a question has been played by a team and the outcome was either correct or wrong, the question expires for the {current} game.   
All the domains of questions: (a) they can have different number of questions; (b) the questions can have different difficulty progressions; (c) the domains can have the same number of questions; (c) the progression of difficulty is the same for all the questions in each domain.
The team in order can choose any domain. But they cannot choose their question or difficulty. The questions and difficulty progress automatically per domain. 
The questions can be multiple answer or single answer.
A team's turn is available until they answer wrong to a question. If they answer correct to a question they keep the turn and can either continue with the same domain (if the domain still has questions) either they can choose another domain. 

Points awarded: (1) flat, no matter the difficulty; (2) complex, based on the difficulty of the questions; (3) other;  these should be set manually in the settings before the game. 

A game finishes when there are no more questions in any domain. The game accepts ties between any team place. 

There can be examples where a team never answers wrong and they can continue with their turn as long as there are questions. So they can finish the game. But that is why this engine accept settings. 

example: 
Team 1, Team 2, Team 3 (in this order)
Domain:  History ([q1, 10], [q2, 20], [q3, 30]), Geography ([q1, 10], [q2,20], [q3,30])

Team  1 chooses history. q1 is played. Correct answer. q1 is never played in the current game. Team 1 continues. Team 1 can choose to change domain. But Team 1 chooses to continue in history. q2 is played. Answer wrong. q2 is never played again in the current game. Team 2 is next in order. Available domains. History and Geography. They choose history. q3 is played. Answer wrong. q3 is never played again in the current game. Team 3 is next. Available domains Geography. They choose geography. q1 is played. Correct answer. Team 3 can choose to change domain... etc The game ends when there are no more questions.

Now, each of these are settings. A setting can have multiple options. So the engine of the game can accept different settings. Infer logical options for each of the question. For example a setting that owns how many consecutive correct turns are allowed. (this way this setting ensures that a team cannot finish alone the questions). Another setting that owns the awarded points can say "If a team completes consecutive correct turns, they get a bonus award {based on the scoring system}".

4.1 The control tab

The control tab get's the viewer. The viewer shows the same screens that are on stage. But with some modifications. These modifications are overlays. To not overload the Action Panel, i want that the operator interact with some elements from the screens through the viewer. Of course they are separate concerns, so that the STAGED screens do not show them or the mouse. They are different. 
Anyhow, for Team order Screen. So with the viewer, the operator can control by clicking the actual components of the screen to give the turn to another team instead of the default order. So the default order of teams will be set in the Game tab. but the operator can change that through the viewer While the game is playing. But the default order still continues once the team (that was selected by the operator) answers wrong. If the operator overrides again, no problem. the default order continues. Example: Deafult order: Team 1 --> Team 2 --> Team 3 --> Team 4. Team 2 answered wrong. The operator opens domain screen. Since an entering dirrectly domain screen the animation between Team 2 and Team 3 is played. But if the operator overrides to team 4, the animation is replayed again between Team 2 and 4, and then the domain screen content is shown. 
This raises another problem, If the operator never shows the Order team, how can he override? because from the viewer he could not click the team name in the order screen. The answer is simple: there are actions in Action Panel. 
The default order engine (or whatever engine own this thing), adapts dynamically so that Team 3 is not overlooked. 
The Action Panel will show a table with all teams and the operator can drag and drop them. But one clarification: All team's turns have to be in sync. A team can play on it's turn infinite number of questions and get points. So, if Team 1, team 2, Team 3, TEam 4 have turns [1,1,0,1] and questions [20,2,0,4], the order cannot go to [2,1,0,1]. All teams have to play their turn [1,1,1,1], questions [20,2,1,4], then the turn can go [2,1,1,1]. The operator cannot override the same team consecutive times. and if turns [1,1,0,0] the order of turns cannot be [2,1,0,0] or [1,2,0,0] or [2,2,0,0]. So by default the engine will enforce to have [1,1,1,1].
