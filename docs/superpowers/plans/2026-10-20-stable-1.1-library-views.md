# Stable 1.1 — library views Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Filters (shared + per tab), sort, group headers and pages of 100 on the four library tabs, from one pure list-view model every tab declares a spec for.

**Architecture:** A pure `listView(items, spec, state)` in `host/listView.ts` does filter → sort → group → page over the full list `catalog_list` already returns; a `useListView` hook joins it to the chrome store (persisted prefs, session state) and owns selection; `LibraryList` renders its output; each page declares a `ListSpec`. No host, IPC or schema change.

**Tech Stack:** React 19, TanStack Table v8 + Virtual, zustand (persist), HeroUI v3, vitest + Testing Library, WebdriverIO e2e.

**Spec:** `docs/superpowers/specs/2026-10-20-stable-1.1-library-views-design.md`

**Tests:** `docs/superpowers/plans/2026-10-20-stable-1.1-library-views-tests.md` (Sonnet's list, with decisions). Each task names the ids it owns.

## Global Constraints

- Branch: work on `release/1.x`; after each task's commit, `git switch main && git merge --no-edit release/1.x`, run `npm test`, switch back. Phases `P13.2` (model, store, hook), `P13.3` (UI + Questions), `P13.4` (other tabs, e2e, docs).
- Nothing on `release/1.x` may import or name Beta-only code (`commands/beta.rs`, `copy/beta.ts`, `BetaWelcomePage`).
- Page sizes exactly `50 · 100 · 250 · All`, default **100**.
- Toolbar order on every tab: **Search · Filters · Sort · Group · View · Status · New**.
- Shared filters: Search, Status (`active` · `archived` · `all`), Changed (`any` · `today` · `7d` · `30d` on `updatedAt`).
- Footer copy: `"{from}–{to} of {rows} {noun}"`, and when rows ≠ distinct items `"{from}–{to} of {rows} rows · {items} {noun}"`; numbers `toLocaleString('en-US')`.
- Continued header: `"{label} · {count} (continued)"`; header: `"{label} · {count}"`.
- Multi-domain mark: `"also in {names}"` (names joined `", "`).
- Bulk under Status All: `"Archive {n} · Restore {m}"`; count line `"{n} selected ({m} on this page)"`.
- Persisted per operator per tab: `sort`, `group`, `pageSize`. Session per tab: filter values, search text, page, collapsed groups.
- Every array or object handed to TanStack from a render is referentially stable (`NO_ROWS` rule, P11.3).
- `chrome.test.ts`'s banned keys stay banned everywhere except the view-state subtrees `prefs.*.lists.*` and `listSession.*`, exempted deliberately with a test that a Play-shaped key outside them still trips.
- Sorting text uses `Intl.Collator('en', { sensitivity: 'base', numeric: true })`; nulls sort last in both directions; *Changed* today = since local midnight, 7 d/30 d rolling and inclusive.
- Group orders: band easy · medium · hard · *Not set*; completeness incomplete · complete; answer single · multiple; Games status playing · ready · archived; *No domain* / *No folder* last.
- Selection holds item ids; collapsing a group drops its items from the selection; a header checkbox selects this page, the bulk bar offers *Select all {n}*.
- The test list's decision table (`…-tests.md`) settles every other open point and wins over a step here.
- HeroUI v3 as shipped; invoke `heroui-react` before writing markup. Studio copy in `copy/`; reuse `LIST.sort*` strings.
- Every task: `npm run typecheck`, `npm run lint`, the task's tests; `npm run map:check` when `package.json` or the contract moves.

## Review Focus

1. **Archiving the last rows on the last page** — the page must move back one, not show an empty page. Test `listView: a page that empties clamps back` (Task 1).
2. **A search that matches more than 500 questions** — every match is listed. Test `search asks for the whole list` (Task 6).
3. **Switching operator mid-session** — the new operator's sort/group/page size apply and the old operator's filters do not leak into their persisted prefs. Test `operator switch swaps prefs, keeps session` (Task 2).
4. **Selecting all, then changing a filter, then pressing Archive** — nothing is archived; the selection was cleared. Test `filter change clears selection` (Task 3).
5. **A group collapsed on page 2, then the sort changes** — page resets to 1, the group stays collapsed, no empty page. Test `collapsed group survives a sort change` (Task 3).

### Task 1: The pure list-view model

**Files:** Create `apps/studio/src/host/listView.ts`, `apps/studio/src/host/listView.test.ts`.

**Interfaces — Produces:**
```ts
export type LibraryTab = 'teams' | 'library' | 'games' | 'operators'
export type PageSize = 50 | 100 | 250 | 'all'
export const PAGE_SIZES: readonly PageSize[] = [50, 100, 250, 'all']
export type FilterValue = readonly string[] | { readonly min: number; readonly max: number } | boolean | string
export interface FilterDef<T> {
  id: string; label: string
  kind: 'multi' | 'choice' | 'range' | 'toggle'
  options?: readonly { value: string; label: string }[]   // multi, choice
  bounds?: { min: number; max: number }                   // range
  /** null value = filter off. */
  test(item: T, value: FilterValue): boolean
}
export interface SortDef<T> { id: string; label: string; compare(a: T, b: T): number; defaultDesc?: boolean }
export interface GroupDef<T> {
  id: string; label: string
  /** One or more groups per item (a question in several domains). order sorts groups ascending. */
  groupsOf(item: T): readonly { key: string; label: string; order: number | string }[]
}
export interface ListSpec<T> {
  tab: LibraryTab
  noun: { one: string; many: string }
  filters: readonly FilterDef<T>[]
  sorts: readonly SortDef<T>[]
  groups: readonly GroupDef<T>[]
  defaults: { sort: { id: string; desc: boolean }; group: string | null; pageSize: PageSize }
  /** Final tiebreak: name/text, then id. */
  tiebreak(item: T): string
  changedAt(item: T): number   // shared Changed filter
}
export interface ListItem<T> { id: string; data: T; view: RecordView }
export interface ListViewState {
  filters: Readonly<Record<string, FilterValue | null>>
  changed: 'any' | 'today' | '7d' | '30d'
  /** Search hits id → score, or null when Search is empty. */
  hits: ReadonlyMap<string, number> | null
  sort: { id: string; desc: boolean }        // id 'match' = Best match (hits score)
  group: string | null
  page: number                               // 1-based
  pageSize: PageSize
  collapsed: ReadonlySet<string>             // group keys
  now: number                                // for Changed
}
export interface ListRow<T> { key: string; item: ListItem<T>; groupKey: string | null; alsoIn: readonly string[] }
export interface ListGroup { key: string; label: string; count: number; continued: boolean; collapsed: boolean }
export type ListEntry<T> = { kind: 'header'; group: ListGroup } | { kind: 'row'; row: ListRow<T> }
export interface ListPage<T> {
  entries: readonly ListEntry<T>[]
  /** Distinct item ids matching, outside collapsed groups — what Select all selects. */
  selectableIds: readonly string[]
  pageIds: readonly string[]            // distinct ids on this page
  rowCount: number; itemCount: number   // rows on screen across pages (no collapsed) · distinct items matching
  page: number; pageCount: number; from: number; to: number
}
export function listView<T>(items: readonly ListItem<T>[], spec: ListSpec<T>, state: ListViewState): ListPage<T>
export function footerText(page: ListPage<unknown>, noun: { one: string; many: string }): string
export function changedSince(changed: ListViewState['changed'], now: number): number | null
```

Order of work inside `listView`: hits (when non-null, keep only hit ids) → each active filter (AND) → Changed → sort (spec compare or hits score desc for `match`; direction; then `tiebreak`, then id) → group (each item expanded to one row per group, key `<groupKey>:<id>`, `alsoIn` = the other groups' labels; ungrouped key = id) → group order (`order` asc, ties by label; rows keep sort order inside) → drop rows of collapsed groups (their header stays, `count` still counts them) → page (clamp `page` to `[1, pageCount]`, `pageCount ≥ 1`; `'all'` = one page) → insert a header before the first row of each group on the page, `continued: true` when that group had rows on an earlier page; a collapsed group's header appears on the page where its rows would have started (or page 1 if it has none on screen).

- [ ] **Step 1: Write failing tests** in `listView.test.ts` against a tiny spec over `{ id, name, n, tags: string[], at }` items:
  - `filters AND across, OR within`: multi `tags ∈ {a,b}` + toggle `n > 5` → only items satisfying both.
  - `a null filter value is off`; `an unknown filter id is ignored`.
  - `Changed today/7d/30d` with `now = Date.UTC(2026,9,20,12)`: items at −1 h, −3 d, −20 d, −40 d → today 1, 7d 2, 30d 3, any 4.
  - `sort by field both ways, ties by tiebreak then id`: two items equal on `n`, named `b` and `a` → `a` before `b` whether `n` sorts ascending or descending (ties always ascend by tiebreak, then id).
  - `Best match sorts by score desc, ties by tiebreak`.
  - `groups ordered by order then label; rows keep sort inside`; `an item in two groups is two rows keyed group:id with alsoIn`; `itemCount counts it once, rowCount twice`.
  - `pages of 100: 250 rows → 3 pages, from/to 101/200 on page 2`; `page past the end clamps back` (Review Focus 1); `page size all is one page`; `pageCount is 1 for zero rows, from=0 to=0`.

  - `a collapsed group keeps its header and count, takes no slots, and its ids are not selectable`.
  - `footerText`: `"101–200 of 1,234 questions"`; with rows 1,310 / items 1,234 `"101–200 of 1,310 rows · 1,234 questions"`; one item `"1–1 of 1 question"`.

  page: ListPage<T>

  setFilter(id: string, value: FilterValue | null): void
  clearFilters(): void                         // filters + changed, not search
