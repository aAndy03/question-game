# Stable 1.1 — library views: the test list

*Proposed by Sonnet 5.5 (medium) on 2026-10-20 from the approved design and the code; decided by the implementer. Ids are owned by the plan's tasks. **U** unit · **I** integration · **E** e2e. [MUST] lands with its task.*

## Decisions on the flags

| # | Flag | Decision |
|---|---|---|
| 1 | `chrome.test`'s banned-key walk would trip on `lists.library`, filter ids `domain`… | Exempt exactly the subtrees `prefs.*.lists.*` and `listSession.*` — view state by construction — and add a test that a Play-shaped key **outside** them still trips. |
| 2 | "All" through JSON | Stored as the string `'all'` (the plan's `PageSize`). P-05 round-trips it. |
| 3 | Selection vs row keys | Selection holds **item ids** (`useListView`); `LibraryList` maps a row key `<group>:<id>` to its item id. |
| 4 | Where Select all lives | Table: a header checkbox selects **this page**; the bulk bar then offers **Select all {n}** (every page). `m` in "(m on this page)" counts distinct items. |
| 5 | Collapsed groups | Header on the page where its rows would start (page 1 if none on screen); footer `rowCount` excludes collapsed rows; header count includes them; **collapsing a group drops its items from the selection**; collapsed state is cleared when the grouping changes. |
| 6 | Nulls in sort | Last in both directions (difficulty, last played, last active). |
| 7 | Group orders | Band: easy · medium · hard · *Not set*. Completeness: incomplete · complete (the ones to fix first). Answer: single · multiple. Games status: playing · ready · archived. |
| 8 | Games "ready" | Active and not playing. A play-state change regroups in place and never resets the page. |
| 9 | Sort by domains | By domain **count**. |
| 10 | Changed | *Today* = since local midnight; *7 d* / *30 d* = rolling, inclusive (`updatedAt ≥ now − n·24h`). Re-evaluated on render, not on a timer. |
| 11 | Text compare | `Intl.Collator('en', { sensitivity: 'base', numeric: true })` — same on every OS; ă = a for ordering. |
| 12 | "Same row in view" | Only the page number is tested; scroll position is not. |
| 13 | Session state | In the chrome store, per tab, not per operator; an operator switch keeps it. |
| 14 | Best match | Appears when the **trimmed** text is non-empty **and** the hits belong to that text (not TanStack placeholder data); never written to prefs. |
| 15 | Search before the list | `useSearch` is enabled only once the list has loaded (`limit = items.length`). Status *All* searches with scope `all` (the host accepts it). |
| 16 | Domain filter vs pane | Picking a domain in the pane clears the Domain filter's values (it is hidden there). A question only in archived domains groups under *No domain*. |
| 17 | Virtualization with headers | Over 200 **entries** (rows + headers) in table view; headers are `h-10` like rows. |
| 18 | Bulk on Games/Operators | None (as today); B-tests apply to Teams and Questions. |
| 19 | Chip vocabulary | The removable filter chip is added to §4.6 in Task 8; no doc-text test (U-24 dropped — prose tests rot). |
| 20 | Performance | `listView` over 3,000 questions with every filter, a sort and domain grouping: median of 5 under **50 ms**; components asserted by commit counts, not time. |
| 21 | e2e data | E-02 imports 120 questions through the Import dialog's paste box. |
| 22 | Aside vs full page | Both paths tested for the session-state return (P-09). |
| 23 | Empty-state actions | *Clear search* when search is on; *Clear filters* when filters are on; both when both. |
| 24 | Many pages | First · last · current ±1, ellipses between (`1 … 4 5 6 … 30`). |
